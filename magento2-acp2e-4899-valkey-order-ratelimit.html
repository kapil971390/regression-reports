Change: ACP2E-4899 — Order Rate Limit feature incompatible with Valkey cache backend

Risk Level

MEDIUM

This commit adds support for Valkey as an alternative to Redis for the backpressure logger system. The system now recognizes both 'redis' and 'valkey' as valid logger types, configured at runtime through dependency injection instead of being hardcoded.

What to Test

  • Step 1: Start the server with di.xml containing the 'valkey' logger type entry. Step 2: Verify the server initialization completes without errors.
  • Step 1: Start the server with di.xml containing the 'redis' logger type entry. Step 2: Verify the server initialization completes without errors.
  • Step 1: Configure di.xml with an unsupported logger type (e.g., 'memcached'). Step 2: Attempt to start the server.
  • Step 1: Start the server with Valkey configured. Step 2: Call the dependency injection container to retrieve a BackpressureLogger instance. Step 3: Verify the retrieved instance has access to the injected valid logger types array.
  • Step 1: Run the unit test suite for ValkeyRequestLoggerTest. Step 2: Verify all test cases pass, including initialization and cache operations.

Where it Can Break

  • If the dependency injection configuration is incomplete or missing the 'valkey' entry, the server fails to start or the backpressure system cannot be initialized
  • If an invalid logger type (neither 'redis' nor 'valkey') is passed to BackpressureLogger at startup, the system accepts it but later fails when trying to use it
  • If the server is upgraded from an old configuration that only knew about 'redis', and the new 'valkey' entry is not added to di.xml, existing setups may break

Edge Cases

  • Server fails to start or backpressure logging is unavailable, causing the system to crash or reject valid requests.
  • Server fails to start or backpressure logging breaks for existing deployments still using Redis.
  • Invalid configuration silently accepted, leading to runtime errors when backpressure logging is accessed, making the failure hard to diagnose.
  • Dependency injection fails to pass the logger types, causing BackpressureLogger to operate without knowing which types are valid, leading to unexpected type validation failures.
  • Missing or incomplete test coverage means the Valkey logger may have bugs that go undetected, causing backpressure tracking to fail in production when Valkey is selected.

Final Verdict

Before approving, verify that: (1) the server starts successfully with both 'redis' and 'valkey' logger types configured in di.xml, (2) attempting to use an invalid logger type is rejected at startup with a clear error message, and (3) test data confirms that both logger types actually record and retrieve backpressure data correctly during runtime.
